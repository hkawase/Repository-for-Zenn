### SMB

> 445/tcp   open  microsoft-ds?

445/tcpでSMBが稼働しているため、まずはSMBへの深掘りを実施する。

:::details SMBとは？
読み方: エスエムビー

正式名称: Server Message Block

意味: Windows界隈でファイル共有・プリンタ共有などを行うためのプロトコル。`\\サーバ名\共有名` でアクセスするアレ。

AD環境では設定不備で匿名アクセス（認証なしアクセス）が許可されていることがあり、ペンテストでは真っ先に覗きにいく対象の一つ。
:::

まずは匿名ログイン（認証情報なしでのアクセス）が可能かどうかを、netexecで確認する。

:::details netexec(nxc)とは？
読み方: ネットエグゼク

意味: SMB/WinRM/LDAPなど、AD関連のサービスに対する認証チェックや情報列挙をまとめて面倒見てくれるツール。旧CrackMapExec（cme）の後継。

`-u`・`-p`にユーザ名・PWを渡して認証が通るかを確認したり、`--shares`で共有フォルダを列挙したりと、何かと使う。
:::

ユーザ名・PWを空（`''`）にして、匿名ログインを試してみる。

```sh
┌──(root㉿5602a1b7889d)-[~/Active]
└─# nxc smb ${RHOSTS} -u '' -p ''
SMB         10.129.99.165   445    DC               [*] Windows 7 / Server 2008 R2 Build 7601 x64 (name:DC) (domain:active.htb) (signing:True) (SMBv1:None) (Null Auth:True)
SMB         10.129.99.165   445    DC               [+] active.htb\:
```

> SMB  10.129.99.165  445  DC  [+] active.htb\:

末尾が`[+]`（緑）になっており、ユーザ名・PW空のまま認証が通ってしまっている。つまり匿名ログイン（Null Session）が可能な状態。

`active.htb\SVC_TGS`というユーザに対する`cpassword`という値が丸見えになっている。

::::details GPP / cpasswordとは？
読み方: ジーピーピー / シーパスワード

正式名称: Group Policy Preferences

意味: グループポリシーの拡張機能で、GPO経由でローカルユーザの作成やパスワード設定などができる仕組み。このとき設定したパスワードが、`Groups.xml`内に`cpassword`という属性で保存される。

:::message alert
問題は、この`cpassword`がAES暗号化されているものの、**復号用の共通鍵をMicrosoftが公式ドキュメントで公開してしまっている**こと(MS14-025)。つまり、`cpassword`の値さえ手に入れば誰でも元のパスワードに戻せる。

現在はこの機能経由でのパスワード保存自体がパッチで塞がれているが、パッチ適用前に作られた`Groups.xml`が`SYSVOL`に残っていると、認証なしで読めてしまうこのケースのように致命傷になる。
:::
::::

:::details なぜこのファイルに目をつけたのか
「GPP + Groups.xml + cpassword」はWindows ADにおける定番の初期侵入ネタのため。

`SYSVOL`（＝今回の`Replication`）は本来ドメイン参加端末なら誰でも読める性質があり、そこに`cpassword`入りの`Groups.xml`が残っていれば認証情報が抜ける…という流れは、ペンテスト・CTF問わず頻出パターン。treeで`Preferences\Groups\Groups.xml`が見えた時点で「これだ」と当たりをつけた。
:::

意味: GPPの`cpassword`を、公開されている共通鍵を使って平文パスワードに復号してくれるツール。Kaliに標準で入っている。
:::

匿名で読めてしまった`SYSVOL`内の`Groups.xml`に、共通鍵が公開済みのGPP `cpassword`が残存していた。

設定不備（匿名READ）とパッチ未適用（MS14-025以前のGPPパスワード残存）の2つが重なり、認証情報が平文で復元できた状況。
:::

## Privilege Escalation

`svc_tgs`は一般ユーザなので、ここからドメイン管理者（Administrator）への昇格を狙う。

LDAP/Kerberosが開いており、ドメインユーザの認証情報も手元にある。この状況だと定石の一つがKerberoastingなので、まずはこれを狙う。

:::details Kerberoastingとは？
読み方: ケルベロースティング

意味: SPN（後述）が設定されているドメインユーザに対して、任意のドメインユーザ権限でサービスチケット（TGS）を要求し、返ってきたチケットに含まれる暗号化部分（＝対象ユーザのパスワードハッシュ由来）をオフラインで解析する攻撃。

ポイントは「一般ユーザの権限さえあれば、SPN付きユーザのパスワードハッシュを要求できてしまう」こと。対象のPWが弱ければ、クラックして成り代われる。
:::

:::details SPN / TGSとは？
SPN（エスピーエヌ / Service Principal Name）: 「このサービスはこのアカウントが動かしてますよ」という紐付けの名前。SPNが付いたアカウント＝Kerberoastingの標的になり得る。

TGS（ティージーエス / Ticket Granting Service チケット）: Kerberosで「このサービスを使っていいよ」という許可証。この中の暗号化部分がサービスアカウントのPWハッシュで作られているため、解析対象になる。
:::

まずは、ドメイン内でSPNが設定されているユーザ（＝Kerberoastingの標的）を、impacket-GetUserSPNsで洗い出す。

:::details impacket-GetUserSPNsとは？
読み方: インパケット・ゲットユーザーエスピーエヌズ

意味: SPN付きユーザの列挙と、そのTGS（ハッシュ）要求をまとめて行えるImpacket[^1] 付属のツール。`-request`を付けると実際にチケットを要求してハッシュを吐き出す。
:::

`svc_tgs`の認証情報でSPN付きユーザを列挙

```sh
┌──(root㉿5602a1b7889d)-[~/Active]
└─# impacket-GetUserSPNs active.htb/svc_tgs:GPPstillStandingStrong2k18
Impacket v0.14.0.dev0 - Copyright Fortra, LLC and its affiliated companies

ServicePrincipalName  Name           MemberOf                                                  PasswordLastSet             LastLogon                   Delegation
--------------------  -------------  --------------------------------------------------------  --------------------------  --------------------------  ----------
active/CIFS:445       Administrator  CN=Group Policy Creator Owners,CN=Users,DC=active,DC=htb  2018-07-19 04:06:40.351723  2026-10-03 14:09:12.242545
```

> active/CIFS:445       Administrator

よりによって、SPNが設定されているのが`Administrator`。つまりKerberoastingで、ドメイン管理者本人のパスワードハッシュを要求できる状態。これが解析できれば一撃でゴール。

`-request`を付けて、実際に`Administrator`のTGSハッシュを要求・取得する（`-o`で保存）。

```sh
┌──(root㉿5602a1b7889d)-[~/Active]
└─# impacket-GetUserSPNs active.htb/svc_tgs:GPPstillStandingStrong2k18 -request -o krb.txt
```

`-request`: SPN付きユーザのTGSを実際に要求する  
`-o`: 取得したハッシュを保存するファイル名を指定

取得したTGSハッシュを、hashcatで解析する。

:::details hashcatとは？
読み方: ハッシュキャット

意味: GPU/CPUを使ってパスワードハッシュを総当り・辞書攻撃で解析するツール。ハッシュの種類ごとに`-m`（モード）を指定する。TGS-REP（etype 23）は`-m 13100`。
:::

:::details なぜシェルを取らずにsmbclientで済ませるのか
フラグを読むだけなら、わざわざpsexec等でSYSTEMシェルを取る必要はなく、管理者権限の認証情報でファイルを読めれば十分なため。

ちなみにHTBなのでやらないですが、実務ではシェルを取る／サービスを作る系の操作はログや成果物が残りやすいので、目的に対して過剰な手数は踏まない、という観点でも理にかなっている。
:::

:::

## まとめ

改めて攻撃チェーンを整理すると以下の通り。

1. SMBの匿名ログイン（Null Session）が有効だったため、`Replication`共有に匿名READでアクセスできることを確認
2. `Replication`（＝`SYSVOL`）内の`Groups.xml`にGPPの`cpassword`が残存しており、共通鍵が公開済み（MS14-025）であることを利用してgpp-decryptで`svc_tgs`の平文PW（`GPPstillStandingStrong2k18`）を復元
3. `svc_tgs`の認証情報で`Users`共有にアクセスし、SMB経由でuser.txtを回収
4. SPN付きユーザをimpacket-GetUserSPNsで列挙したところ`Administrator`にSPNを発見、Kerberoastingで`Administrator`のTGSハッシュを取得
5. hashcat（`-m 13100`）でTGSハッシュをクラックし、`Administrator`のPW（`Ticketmaster1968`）を取得
6. 取得した管理者認証情報で`(Pwn3d!)`を確認し、`Users`共有へsmbclient接続してroot.txtを回収（ドメイン完全掌握）

Easyだけあって一本道だけど、「GPP cpassword」と「Kerberoasting」というWindows ADの超定番ネタが2つとも詰まっていて、入門用として本当によくできたマシンだと思う。最初に`--shares`で`Replication READ`を見た瞬間に「あ、これGroups.xmlやつだ」と反応できるようになったら一人前、という気がする。

ちなみに、SPNが`Administrator`に付いていたおかげで一撃で終わったけど、本来Kerberoastingは「SPN付きの弱めのサービスアカウントを踏み台にして、そこから更に昇格」という流れになることが多い。今回は踏み台がゴール本人だったという、ある意味ラッキーなマシン。
