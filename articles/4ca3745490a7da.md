## はじめに

どうも、セキュリティベンダーでコンサル/脆弱性診断/ペンテストなどをチョットダケやってるkawaseです。

画像共有サービス「Gyazo」で発生した不正アクセスについて、要点だけさくっとまとめました。第一報の後に追加の漏えいの判明やサービス再開があったので、その続報もあわせて整理しています。

通勤時間のオトモにでも( ´･ω･)⊃旦

## ざっくり概要

| 項目 | 内容 |
| --- | --- |
| 企業名 | 株式会社Helpfeel |
| サービス | Gyazo(画像共有サービス) |
| 被害件数 | ユーザー情報 約2,362万件、画像のメタデータ 約4.9億件+削除済み画像のメタデータ 約1.74億件 |
| 公表日 | 2026年9月16日(第一報)、9月25日(第二報)、9月27日(サービス再開) |
| 原因 | 画像アップロードサーバーの脆弱性を突いた不正アクセス |
| 現状 | 9月27日にサービス再開。過去の画像は本人のみ閲覧できる状態に変更 |

## 時系列

- **9月11日** 画像アップロードサーバーの脆弱性を突いた不正アクセスが発生し、同日中に異常を検知[^1]
- **9月12日未明** 侵入経路の遮断と脆弱性の修正を完了[^1]
- **9月14日** データが外部に流出したことを確認[^1]
- **9月16日** 第一報を公表[^1]
- **9月25日** 第二報。削除済み画像のメタデータ約1.74億件も流出していたと公表[^2]
- **9月27日** サービスを再開[^3]

## 漏えいした情報

- **ユーザー情報(約2,362万件)**: 氏名、メールアドレス、パスワードのハッシュ値、ユーザーID、端末ID、ログインセッションID、X連携トークン、Google SSOのメールアドレス、プロフィール情報、契約プランなど[^1]
- **画像のメタデータ(約4.9億件)**: 画像ID、アップロード元のIPアドレス、User-Agent、EXIFの位置情報、画像のOCRテキスト、非公開画像のパスフレーズのハッシュ値など[^1]
- **削除済み画像のメタデータ(約1.74億件)**: 主に2023年2月以前に削除された画像のもの。画像ファイルそのものの流出は確認されていない[^2]

決済カード情報は対象外です[^1]。

## 現状

- 9月27日にサービスを再開。不正アクセス以前にアップロードされた画像は、いったん所有者本人のみが閲覧できる状態に統一。本人が内容を確認して「配信を再開する」を選ぶと、元の公開範囲に戻る[^3]
- 二次被害を防ぐため、パスワードの変更を依頼。ほかのサービスで同じパスワードを使っている場合はそちらの変更も呼びかけている[^3]
- 外部の専門機関と調査を継続し、認証・認可やアクセス制御の見直し、監視体制の強化を進めるとしている[^3]

## コメント

ユーザー情報だけでなく、画像に付随する位置情報やOCRテキストまでデータとして持っていたことが、被害の範囲を広げています。さらに第二報では、ユーザーが削除したはずの画像のメタデータまで残っていて流出したことがわかりました。

「削除したのに裏では残っていた」というのは利用者からするとかなりショックな話で、データを本当に消せているかという点はサービス設計の段階で考えておくべきポイントだと感じます。画像本体は消すからいいだろう、という判断でメタデータのみ残し、何かに使っていた可能性もあるのかなとは思っています。

なお、この件は[9月のインシデント振り返り記事](https://zenn.dev/hkawase1220/articles/61aff172d8899e)でも取り上げています。
